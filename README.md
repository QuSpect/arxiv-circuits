# arxiv-circuits

**Key quantum circuits from recent arXiv quant-ph papers, as OpenQASM 2.0.**

[中文说明](README_CN.md)

This dataset contains **55 quantum circuits** from **41 papers** submitted to arXiv quant-ph
(primary or cross-listed) between **2026-06-28 and 2026-10-28**. Each circuit was read gate by gate
from a quantikz / qcircuit diagram in the paper's LaTeX source, checked against the paper, and
stored as a self-contained OpenQASM 2.0 file. A manifest links every circuit to its source paper and
records how it was verified.

The circuits are ones the papers propose, construct or study as a main object — algorithms,
ansätze, encodings, decompositions, simulation steps, state preparations and arithmetic — at 3 to
16 qubits. They are intended as
realistic, recent, independently sourced test inputs for quantum compilers, simulators and circuit
analysis tools.

The dataset was originally built for the compilation benchmark of
[quspect](https://github.com/QuSpect/quspect).

## Inclusion rules

- **Exact sources only.** Circuits are taken gate by gate from quantikz / qcircuit diagrams in the
  paper's LaTeX source (or from OpenQASM code in the text). Nothing is reconstructed from prose,
  transcribed from images, or assembled from several figures. No paper-specific `.qasm` files were
  found in code repositories accompanying the papers (the only repository with `.qasm` files held an
  unmodified copy of QASMBench).
- **Concrete circuits only.** Diagrams with abstract boxes (U, W, QFT, PREP, oracles, ...),
  ellipses (`\vdots` / `\cdots`, i.e. generic n-qubit templates), wires standing for several qubits,
  or that are only fragments are excluded.
- **Unitary part only.** Final and mid-circuit measurements are removed; circuits whose meaning
  depends on mid-circuit measurement, reset or classical feed-forward (e.g. syndrome-extraction
  gadgets) are excluded. Inputs labelled `|1⟩` / `|+⟩` / `|−⟩` become the corresponding X / H gates.
- **Key circuits of the paper.** A circuit must be something the paper proposes, constructs or uses
  as a main object. Incidental textbook gadgets (Bell/GHZ preparation, a generic QFT sketch, gate
  identities) are excluded. At most 3 circuits per paper, and only structurally different ones (of
  several instances of one template, the most representative is kept).
- **Minimum size.** ≥ 3 qubits and ≥ 6 CNOTs after decomposition into CNOT + single-qubit gates.
- **Parameters.** Where the paper gives concrete angles, they are used. Otherwise each symbolic
  angle gets a fixed pseudo-random value derived from its symbol name (SHA-256 of the name mapped to
  [−π, π), 6 decimals), so the files are reproducible; see `params_source`. Angle values do not
  change the circuit structure.

## Verification

Every circuit went through:

1. **Gate-by-gate check** of the conversion against the LaTeX diagram (controls, open controls,
   targets, rotation axes, wire order).
2. **Unitary-equivalence assertion** between the normalized QASM and the circuit parsed from the
   diagram (no idle wire is borrowed as a |0⟩ ancilla during translation).
3. **Functional verification** by simulating the final QASM and checking what the paper says the
   circuit does (prepared state, implemented unitary or phase, truth table, gate counts stated in the
   paper, ...); the result is recorded in the `verification` field. Where no functional statement
   can be checked, the field says `faithfulness only`.
4. **Re-generation check**: before release, every circuit was regenerated by the converter from the
   paper source and compared (unitary equivalence) with the reviewed file, and loaded with qiskit,
   pytket and quspect.

All review decisions, including rejections and their reasons (also for candidates produced by
earlier converter versions), are in `review_log.jsonl`.

## Selection funnel

| Stage | Count |
|---|---|
| quant-ph papers (including cross-lists) | 8158 |
| Keyword pre-filter (circuit / qubit / gate / algorithm, ...) | 4983 |
| LaTeX source downloaded | 3411 |
| Source contains quantikz / qcircuit / OpenQASM | 448 papers, 1514 diagrams |
| No abstract gates, exactly convertible | 441 diagrams |
| Candidates meeting the size threshold | 141 diagrams |
| Per-candidate review | 141 |
| Accepted | 55 circuits (41 papers) |

For 2026-08-28 to 2026-10-28, all keyword-matched papers were downloaded. For 2026-06-28 to
2026-08-27, only the 688 papers with "circuit" in the title or abstract were downloaded: in the
later period, which was processed first, 24 of the 25 accepted papers belonged to that group, while
the remaining papers are slow to download from arXiv and yielded very little.

Most papers could not contribute because their circuit figures are pre-rendered PDF/PNG images (no
circuit description in the source), or because they use abstract boxes or ellipses for generic
structures, which the exact-source rule excludes.

## File format

**QASM files** (`circuits/*.qasm`):

- OpenQASM 2.0 with `include "qelib1.inc";`, a single register `qreg q[n];`, no classical register,
  no measurements or barriers.
- Gates are restricted to `id h x y z s sdg t tdg rx ry rz p u3 cx cz cp crz swap ccx` (accepted by
  common OpenQASM 2.0 readers such as qiskit, pytket and quspect); `ccx` is kept as a native gate.
  Angles are in radians. Global phase is not represented.
- `q[0]` is the top wire of the drawn diagram, counting downwards; wires idle in the diagram are
  dropped. This can differ from the paper's own qubit labels (noted in `review_log.jsonl` where
  relevant).
- File names: `arxiv<arXiv id>_<name>_<n_qubits>.qasm`.

**Manifest** (`manifest.csv` / `manifest.jsonl`, identical content, newest paper first):

| Field | Meaning |
|---|---|
| `file` | file name in `circuits/` |
| `arxiv_id` | arXiv identifier including the version the circuit was taken from |
| `url` | `https://arxiv.org/abs/<arxiv_id>` |
| `title` | paper title |
| `submitted` | first submission date (YYYY-MM-DD) |
| `primary_category` | primary arXiv category |
| `description_zh` | one-sentence description (Chinese) |
| `description_en` | one-sentence description (English) |
| `category` | `algorithm`, `ansatz`, `arithmetic`, `decomposition`, `simulation`, `state_prep` or `other` |
| `n_qubits` | number of qubits |
| `n_2q` | number of two-qubit gates in the file as written (`cx`, `cz`, `cp`, `crz`, `swap`) |
| `n_ccx` | number of `ccx` gates |
| `n_2q_ccx6` | `n_2q + 6 * n_ccx` (counting a Toffoli as 6 CNOTs) |
| `depth` | circuit depth of the file as written (every gate counts as one layer step, `ccx` included), as computed by qiskit `QuantumCircuit.depth()` |
| `source` | diagram kind and its position `k` among the diagrams of the paper source (matches `diagram` in `review_log.jsonl`) |
| `params_source` | where the angle values come from |
| `verification` | what was checked and the result |
| `flags` | converter flags, e.g. `measure_dropped` |

**Review log** (`review_log.jsonl`): one record per reviewed diagram with `arxiv_id`, `title`,
`diagram` (position `k`), `decision` (`accept` / `reject`) and `reason`.

## Usage

With qiskit:

```python
import json
from qiskit import QuantumCircuit

rows = [json.loads(line) for line in open("manifest.jsonl", encoding="utf-8")]
for row in rows:
    qc = QuantumCircuit.from_qasm_file(f"circuits/{row['file']}")
    assert qc.num_qubits == row["n_qubits"] and qc.depth() == row["depth"]
print(len(rows), "circuits loaded")
```

With [quspect](https://github.com/QuSpect/quspect) (`pip install quspect`):

```python
from pathlib import Path
from quspect.ir import qasm2_loads

circ = qasm2_loads(Path("circuits/arxiv2610.25350_su3_singlet_prep_6.qasm").read_text())
print(circ.num_qubits, len(circ))  # 6 qubits, 14 instructions
```

To check the whole dataset (manifest statistics recomputed from the QASM, gate set, links, loading):

```bash
pip install -r tools/requirements.txt
python -I tools/check_dataset.py
```

## Reproducing the extraction

The full pipeline (arXiv metadata and source download, diagram conversion, review batches,
assembly) is in [`tools/`](tools/), with instructions in [`tools/README.md`](tools/README.md) and the
review specification in [`tools/REVIEW_BRIEF.md`](tools/REVIEW_BRIEF.md). Run the converter tests with
`python -I tools/tests/run_all.py`.
